# Fasciculation Detection — Synthetic Data (BBVI Validation)

> Bayesian Black-Box Variational Inference (BBVI) with EM optimization applied to **synthetic fasciculation video** for method validation against known ground-truth rotation angles. Uses multi-scale image pyramids, independent per-ring rotation estimation, and product-of-Gaussians Bayesian prior fusion. Includes adaptive Centre-of-Rotation (COR) tracking with zoomed inset trajectory visualization.

## Project Description

This repository applies the Bayesian BBVI + EM rotation estimation pipeline to the **synthetic fasciculation video** generated by the `Fasciculation-Simulation` repository. Because the ground-truth rotation angles are known for the synthetic data, this script serves as a **validation and benchmarking tool** — allowing direct comparison between estimated and true rotation values.

Key features compared to the ALS version:

- Processes the full 40-frame synthetic video (frames 1–40) with a configurable frame step (`FRAME_STEP=3`)
- Larger ROI: `240–740 x, 124–624 y` (500×500 px)
- Coarser ring spacing: `radii = 10, 30, 50, ..., 190` px (10 rings, step 20)
- Fewer MC samples (`S_mc=10`) balanced by more EM iterations (`E=40, M=30`)
- Enhanced center trajectory plot with **zoomed inset panel** and per-frame annotations
- Posterior variance diagnostic plot included

The initial rotation angles (`ring_initial_rotation_values.csv`) are loaded from the `Fasciculation-Simulation` output directly — no optical flow step required for synthetic data.

---

## Objectives

1. **Validate the BBVI pipeline** against known synthetic ground-truth rotation angles.
2. **Estimate per-ring rotation angles** from consecutive synthetic frame pairs.
3. **Track the Centre of Rotation (COR)** adaptively across frames.
4. **Fuse temporal and spatial uncertainty** via product-of-Gaussians Bayesian priors.
5. **Visualize convergence** — rotation trajectories, MSE, ELBO, noise variance, posterior variance, and COR trajectory with zoom inset.

## Configuration Parameters

| Parameter        | Default            | Description                                                        |
|------------------|--------------------|--------------------------------------------------------------------|
| `video_path`     | —                  | Path to synthetic `.mp4` video                                     |
| `csv_init_angles`| —                  | Path to initial rotation angles CSV                                |
| `FRAME_START`    | 1                  | First frame (1-based)                                              |
| `FRAME_END`      | 40                 | Last frame (1-based, inclusive)                                    |
| `FRAME_STEP`     | 3                  | Gap between paired frames (frame i vs frame i+3)                  |
| `xmin/xmax`      | 240, 740           | ROI x-bounds in pixels                                             |
| `ymin/ymax`      | 124, 624           | ROI y-bounds in pixels                                             |
| `radii`          | `arange(10,200,20)`| Ring radii — 10 rings at 20px intervals                            |
| `pyramid_scales` | [0.25, 0.5, 1.0]   | Multi-scale pyramid levels (coarse to fine)                        |
| `S_mc`           | 10                 | Monte Carlo samples per ELBO estimate                              |
| `OUTER_EM_ITERS` | 50                 | Outer EM iterations per pyramid level                              |
| `E_UPDATES`      | 40                 | E-step (variational) gradient updates per outer iteration          |
| `M_UPDATES`      | 30                 | M-step (center + noise) gradient updates per outer iteration       |
| `Elr_levels`     | [1e-4, 1e-4, 1e-4] | E-step Adam learning rates per pyramid level                       |
| `Mlr_levels`     | [1e-4, 1e-4, 1e-4] | M-step Adam learning rates per pyramid level                       |

### Why `FRAME_STEP=3`?

The synthetic video has 40 frames over ~1.3 seconds (30 fps). A step of 3 increases the apparent motion between paired frames, making the rotation signal larger and easier to estimate — particularly useful when validating against ground truth where the true angle difference is small per frame.

## Algorithm Overview

The algorithm is identical to the ALS repository with the following additions:

### Frame Step Pairing
Instead of consecutive pairs `(i, i+1)`, pairs are formed as `(i, i+FRAME_STEP)`. This gives a larger rotation signal per pair at the cost of temporal resolution.

### Enhanced COR Visualization
The centre-of-rotation (COR) trajectory plot includes:
- Per-frame index annotations on each point
- A **zoomed inset panel** (`zoomed_inset_axes`) showing fine-grained COR drift
- Connecting lines between the inset and main plot (`mark_inset`)

### Direct CSV Initialization
The initial rotation CSV (`ring_initial_rotation_values.csv`) comes directly from the `Fasciculation-Simulation` output — the exact ground-truth values used to generate the video. This means the BBVI starts from the true answer, and convergence quality can be measured against it.

For full algorithm details (BBVI ELBO, product-of-Gaussians fusion, coarse-to-fine propagation), see `docs/algorithm_overview.md`.

## Known Limitations

- Paths are hardcoded — update for local use.
- No automatic comparison against ground-truth CSV — visual inspection only.
- `FRAME_STEP=3` means the last `FRAME_STEP-1` frames have no outgoing pair.
- Square annular masks approximate circular rings; boundary pixels are approximate.
- CPU execution is significantly slower than GPU.

## Related Repositories

This repository is **Stage 3a** in the full pipeline:

**Stage 1 — [Fasciculation-Simulation](https://github.com/ShzdiTrnum/Fasciculation-Simulation)**
> Generates synthetic video and ground-truth rotation CSV.

**Stage 2 — [Optical-Flow](https://github.com/ShzdiTrnum/Optical-Flow)**
> Optical flow rotation estimates on synthetic and real data.

**Stage 3a — This repository** ← Synthetic validation
> BBVI on synthetic video. Validates method against known ground truth.

**Stage 3b — [Fasciculation-Detection-ALS](https://github.com/ShzdiTrnum/Fasciculation-Detection-ALS)**
> BBVI on real ALS ultrasound. Clinical detection pipeline.

### Full Pipeline

```
Fasciculation-Simulation

        ▼
   Optical-Flow

        │           │
        │           ▼
        │   Fasciculation-Detection-Synthetic  ← you are here
        │           │  validation plots + error vs ground truth
        │
        └──→ normalized rotation CSV (ALS)
                    │
                    ▼
        Fasciculation-Detection-ALS
                    │  clinical rotation estimates
```
